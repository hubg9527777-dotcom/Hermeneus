# 重新发布 Hermeneus v1.0.0（build 2）

准备目录：`dist/v1.0.0-reissue/`。不要上传旧的 `dist/v1.0.0/` 或 QA 候选文件。源代码、安装包、安全报告、依赖清单、SBOM、发布说明与校验清单已经绑定在同一份发布记录中。

## 先检查（不提交、不推送、不上传）

在项目根目录运行：

```sh
python3 scripts/publish_v1.py
```

出现 PASS 后，维护者执行下面命令才会真正发布：

```sh
python3 scripts/publish_v1.py --publish
```

需要 Python 3.11+、Git、已登录且有仓库写权限的 GitHub CLI。未登录时先执行 `gh auth login`，不要把令牌写入脚本或聊天。脚本固定目标为 `secure-artifacts/Hermeneus` 的 main 分支与 v1.0.0。

## 命令会做什么

1. 重新验证受审源码、原生配方、安装包、源码 ZIP、固定附件集合与 SHA-256。
2. 确认仓库、分支与远程状态，提交此次受控源码修改。私有审计目录、验证日志、音频、环境文件不在提交/源码导出清单内。
3. 旧本地 v1.0.0 标签先复制为带时间的本地备份，再指向本次新提交；只推送 main 与目标标签，不推送其他本地旧标签，不强推远程。远程目标标签如指向不同提交会停止。
4. 创建 GitHub 草稿并上传 8 个固定附件；逐个核对 GitHub 提供的 digest，没有 digest 时回下载核对。
5. 只有全部匹配才公开 Release 并设为 latest。**执行带 --publish 的命令包含实际对外发布授权，不会再次弹出确认。**

若网络中断，保留的草稿仍未公开。源码、附件未改变时可重试同一命令；已有公开 v1.0.0、陌生草稿附件、源代码漂移或远程分支分歧都会停止，需维护者核查。不要用强推或手动关闭安全门禁来绕过提示。

当前远程 v1.0.0 Release/tag 在审核时均不存在，本地旧标签仍存在。删除 GitHub Release 不总会删除标签，本脚本会重新检查，不能只凭历史检查结果覆盖它。
